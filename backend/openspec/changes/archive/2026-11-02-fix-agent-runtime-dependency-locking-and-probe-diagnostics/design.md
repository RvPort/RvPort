## Context

本轮重新打开同名活动 change；上一轮归档及已同步主规范是基线，历史证据仍保留。本轮只替换 Codex CHAT 的转换实现及必要探针执行路径，不重做 DSH HMR 修复、不升级其他 CLI。主规范在本轮 sync 前不改写。

当前 `CodexAgentRuntimeAdapter` 在 CHAT 路径创建自有 `CodexChatBridge`；`ModelProfileService` 的异步 probe 和旧测试入口在 backend 直接调用 `CodexProviderProbeService`。业务任务在 worker 执行，因此仅替换 Adapter 不足以满足代理只在 worker 运行的要求。

2026-10-30 的本地 Docker PoC 使用 OpenCodex 2.94.0、Codex 0.165.0：真实文本、读/写文件、custom apply_patch、动态 provider 变更和并发隔离通过。运行时断开外网，mock 为唯一 CHAT 上游，未调用现有 Java 转换器。详细私有证据位于仓库根 `.migration-reports/opencodex-worker-poc-20261030/REPORT.md`。可移植事实与风险记录在本文，不要求他人的 checkout 具有该私有目录。

候选来自 [lidge-jun/opencodex](https://github.com/lidge-jun/opencodex)，npm 包 `@bitkyc08/opencodex@2.94.0`；Bun 1.4.4 随依赖安装。安装体积约 235 MiB，两个代理各自的 Node+Bun RSS 采样约 200–300 MiB，启动约 2 秒；这些不是容量承诺。PoC 证明协议路径可行，未证明所有上游、异常协议和生产生命周期已验收。

## Goals / Non-Goals

**Goals:**

- 第三方完成 Responses ↔ Chat 语义转换，项目只维护配置、请求准入、执行监管、诊断和测试契约。
- Codex CHAT 在现有 worker 内按执行启动独立 OpenCodex；业务任务、异步管理探针、旧兼容测试均使用该路径。
- 动态 profile 不需要人工维护代理注册表；执行快照有确定的更新/删除生效时机。
- 完整依赖冻结、原生路径回归、可靠取消与超时、独立单元测试和全量质量门槛可重复验证。

**Non-Goals:**

- 不新增 Compose 基础设施、外部代理/数据库、公开代理 API 或常驻共享模型网关。
- 不修改前端，不改变 profile wireApi 枚举、三项通用 probe 或权限契约，不为 DSH/OpenCode 增加转换。
- 不自动跟进最新包、不维护独立第三方 fork（允许下述用户批准的受控补丁）、不保留自有转换器作为静默 fallback。
- 不连接远程测试，不安装/修改 dev/test，不自动 sync、archive、commit、push 或部署。

## Decisions

### 1. 明确第三方实现和项目边界

采用固定 OpenCodex 2.94.0。删除原自有 CHAT/Responses 消息映射、SSE 转换和 freeform 语法转换的生产路径；保留可复用且与第三方无关的预算、监管、公共诊断及契约夹具。旧转换器不作为 OpenCodex 启动失败后的备选。

项目可实现一个小范围的 loopback 请求准入层，负责临时 token、允许路径、固定模型、请求大小、预算及取消，校验通过后将 Responses 请求/响应原样交给 OpenCodex。它不映射角色、工具、SSE 或 Chat 消息，也不替模型生成结果。优先使用固定版本能够被证实的原生准入能力；若原生配置不能满足既有安全边界，使用上述项目准入层，而不是重新实现转换器。

转换语义保留现有 `codex-chat-protocol-bridge` 的工具、多轮、流式终态、异常和能力边界契约。第三方代码不能因“是依赖”而免除行为验收；若缺失必须能力，任务保持未完成并报告具体差距，不能改回自研转换或缩减标准。

### 2. 单执行单实例，严格限定运行位置

```text
backend 管理 API ──现有 RabbitMQ 内部探针任务──► worker
                                                │
worker Codex CHAT ─► 本地准入 ─► OpenCodex ─► 当前 profile CHAT 上游
worker Codex RESPONSES ────────────────────► 当前 profile RESPONSES 上游
```

代理只由 worker 运行角色启动；同一构建镜像包含依赖不等于 backend API 角色可以启动代理。CHAT Adapter 若在错误角色直接执行，应返回明确受控错误，不能退回 backend 自行启动。原生 RESPONSES 与其他 Agent 保持现有执行位置及路径。

每次执行配置只含一个固定 provider、固定 model 和该 profile 的快照。使用独立的 `OPENCODEX_HOME`、`CODEX_HOME`、临时配置目录、代理/准入端口与随机认证材料；启动前创建最小权限目录，结束后清理。Codex 不读取用户宿主配置。

前台启动 `ocx start`，不用交互式 init、服务安装或管理 API 注册 provider。关闭自动更新、catalog 定时刷新、Claude intercept、客户端自动集成、无关 sidecar/模型回退；对固定版本逐项核实实际开关及启动行为，不仅把未经验证字段写入 JSON。禁止上游/模型/密钥 fallback。Codex base URL、模型和传输配置由项目显式设置，不依赖 OpenCodex 对 Codex 用户配置的自动重写。

并发受 worker 的任务限额和一个共享代理执行限额控制，排队消耗同一截止预算；探针和业务任务不能分别绕过总限额。资源预算据本地当前镜像测量确定并记录，不能用简单加大内存掩盖泄漏。

### 3. 配置回退和默认路由必须在发请求前拦住

PoC 已发现：本地地址未显式允许时配置会被判无效并回退默认 10100 端口；删除 provider 后，旧的 `provider/model` 可能落到默认 provider，即使关闭 fallback 仍如此。

因此在启动前对生成配置做严格验证；启动后核对进程存活、实际 loopback 端口、实例身份、模型列表及有效 provider/上游配置（通过受保护本地管理读取或等效可验证机制）。发现配置无效备份、额外 provider、错误端口/模型、隐式默认配置或意外监听即终止，不开始 Codex。不能仅以 `/healthz` 返回 200 判就绪。

Codex 只能访问准入允许的 Responses 推理路径及确有需要的只读模型路径；管理 API、GUI、任意 URL/模型、非预期 Host/目标及错误 token 必须拒绝。准入上游固定为本次 loopback OpenCodex；OpenCodex 上游固定为快照。模型名要精确匹配，避免未知路由进入默认 provider。误用、过期、其他任务 token 的请求不得触达模型上游。

代理的直接端口和管理凭据仅 worker 监管器持有，不向 Codex 配置发布；这些限制隔离正常调用及误路由，不宣称在共享同一 UID 的容器内提供防恶意本地进程的强隔离。现有任务本地执行权限边界不扩大。

### 4. 密钥由受管代理使用，保存范围明确

原规范禁止真实密钥出现在任何子进程配置，适用于 JVM 内转换器。本轮改为允许真实密钥进入 OpenCodex 专属配置文件，目录 0700、文件 0600、位于受管临时运行区，生命周期由执行监管器拥有。Codex 仅获取准入 token，真实上游密钥不得出现在 Codex 环境/命令/工作区、公共日志或队列消息中。

不把配置目录放在共享持久 volume 或模型工作区，不导出生产凭据文件作为验收报告；正常、异常、取消、worker 重启的清理均覆盖配置、代理日志和临时状态。检查 OpenCodex 默认日志、备份、数据库和诊断输出是否复制敏感内容；关闭内容日志或约束到临时受限目录并销毁，公共诊断仍使用白名单事实。禁止跨源重定向携带凭据。

### 5. 动态 profile 以执行时快照为准

新增 profile 后第一次执行即可生成代理配置，不需要额外注册。排队项只持有 profile/runtime/操作引用与截止时间，不保存明文凭据；worker 在领取时重新检查存在性、启用状态和授权条件，原子解析当时有效配置并冻结。

- 领取前更新：使用领取时的新版本；领取前删除/禁用：明确失败，无上游请求。
- 领取后更新：当前执行继续使用已冻结版本，新执行使用新版本，不能半途切换 key/base URL/model。
- 领取后禁用/删除：已开始执行按快照完成或由既有取消机制终止；不是自动撤销全部在途任务。新执行必须拒绝。已有“绑定中的 profile 不得删除”规则保留。
- 临时覆盖：仅属于本次兼容请求；如跨 worker 需要持久化，使用现有加密能力保存短期执行快照，设置过期/消费清理；不修改已保存 profile，也不将明文放进 RabbitMQ。

以上规则同样适用于 native/CHAT 的配置解析边界，实际代码修改限制在本次受影响调用链；不扩展为全项目配置版本治理。

### 6. Codex CHAT 探针通过现有基础设施调度

为 Codex CHAT 的探针增加内部 job/执行记录及既有 RabbitMQ 上的专用内部路由，复用现有数据库、连接、认证和 worker 运行角色。消息只携带执行 ID、关联 ID、有效期及必要非敏感标识。job 在发布前持久化，包含状态、截止时间、领取者/租约和结果引用；发布失败可恢复且有最终失败状态。

worker 以原子领取保证单一执行所有者；重复投递不重复启动 Agent、不重复创建最终结果；失联/租约过期按预算有限恢复，旧所有者返回不能覆盖新终态。任务保留唯一结果关联，运行中的模型调用不得被通用无限重试重新收费。不得借用必须有项目/业务阶段的任务类型伪造 project 或绑定；内部 probe job 不暴露为新业务功能。

多 runtime run 的非 Codex CHAT 分项保持原路径，结果由统一汇总器在真实终态后归并。worker 不可用、消息过期、启动失败或领取失败必须产出明确失败/待执行状态，不能让整次 run 永远 RUNNING。旧同步 `:test` 接口通过有界等待内部结果返回原格式；等待超时应终止/过期对应执行，不能遗留后台调用或改变为前端必须适配的新响应类型。

按需扩展现有 probe 执行表或新增最小内部表及迁移；所有结果持久化幂等、对历史结果只读。新增诊断说明提供中文和英文字段。只迁移 Codex CHAT，不迁移 DSH/OpenCode 或独立连通性测试。

### 7. 同一预算、可靠回收和诊断

排队、代理就绪、CLI、上游连接/流和重试共享本次绝对截止时间；保留原有单项 probe 和阶段预算，不把代理启动耗时排除在外。为本地上游显式配置有限的连接/流等待，不能使用第三方对本地地址默认无限等待。

取消先阻止新请求并停止 Codex/代理，再在现有有限清理宽限内收回所属进程组/后代和临时资源。PoC SIGTERM 会排空，不能以已发信号代表清理完成；宽限到期强制终止本执行的 Node/Bun/Codex 全部后代，检查无活动端口和后台上游请求，复用现有 subreaper 解决孤儿/僵尸进程。不能杀同容器其他任务或按进程名全局清理。

诊断区分排队/启动配置/启动就绪/上游连接/协议/执行超时/取消/清理失败，记录 CLI 与代理版本、执行/清理耗时和安全路由。原始 stderr、上游正文及凭据不进入公共响应，未知原因明确未知。

### 8. 依赖与验收

OpenCodex 使用独立受管子目录的精确 package.json/lock 安装，避免 npm 扁平化改变已验证 DSH 依赖树；是否合并目录必须有等价冻结证据。Bun 与实际平台包、native/optional 依赖、安装脚本生成文件及下载来源纳入清单校验，校验器识别缺包/额外包/完整性偏差；不能只记录主包版本。两次空 volume `npm ci` 比较规范化清单，固定 Node/npm，关闭运行期更新。

第三方软件许可证与 notices 随发布清单记录，不在自有代码覆盖率统计依赖源码。所有自有新增/修改/复用模块必须有单元测试：配置/准入/生命周期、锁校验脚本、调度状态/幂等/过期、结果聚合和脱敏。Java 全量 `mvn -B clean verify`，Python 使用现有 coverage 命令并将新增脚本纳入 source；行和分支分别检查整体及完整受影响模块各至少 90%，纳入未加载源码。

真实 Codex 本地 fixture 覆盖 native/CHAT、文本、读写、custom apply_patch、连续多轮/多工具、UTF-8/SSE 分块、无终态/畸形流、截断/用量、401/429/5xx、未知模型、错 token、配置回退、端口冲突、并发、超时和取消。不能用“mock 最终 JSON 正确”代替实际工具和文件检查。继承主规范的未证明能力必须补证。

从根目录用当前候选源码限资源顺序构建全部默认 Compose 服务，一次 `docker compose up -d --wait` 启动隔离 stack；通过正常 API 验证 profile 动态创建/更新、原生及 CHAT 探针、旧入口、混合 runtime 聚合、worker 故障收敛、两个业务阶段，确认 backend 不启动代理且无新增服务/主机端口。前端不改代码，执行既有 lint/类型/普通单测/构建（保留既定覆盖率例外）。只使用隔离数据库/模拟上游，所有动作本地 Docker。

报告记录精确命令、退出码、源码/镜像/lock 哈希、covered/total、排除项、模块清单、健康/日志与清理。报告目录使用本轮独立后缀，避免覆盖原验收。覆盖率或任何必需验证失败时不得勾选完成或提示归档。

## Risks / Trade-offs

- [第三方行为不能满足现有协议契约] → 先完成能力矩阵；明确失败并报告，不写第二个转换器或静默删除要求。
- [默认配置/未知模型回退] → 就绪核验、单 profile 快照、精确请求准入及负例回归。
- [约 200–300 MiB/实例及启动延迟] → 共用并发闸门、剩余预算检查、当前镜像测量，无证据不承诺任意并发。
- [探针迁移漏旧入口或重复执行] → 调用链清点、幂等领取、绝对截止、迟到结果保护及混合 run 测试。
- [进程或临时凭据残留] → 独立目录、subreaper、有限清理、启动前回收本 worker 遗留资源；拒绝跨实例清理。
- [历史覆盖率缺口需无关重构] → 报告差距并请求扩大范围，不擅自降低门槛。

## Migration Plan

1. 以已同步主规范为基线完成本轮 delta 和任务；保留原归档，所有本轮任务从未完成开始。
2. 在本地锁定第三方与验证配置/行为边界，实施受管实例和 Codex CHAT 探针分派，删除生产自研转换路径。
3. 完成本轮全量单测、覆盖率、CLI 与完整 Compose 验收，更新文档；再由用户要求 sync/archive。若同日同名归档目录冲突，保留旧历史并采用 CLI 支持的无覆盖方式记录第二轮，不覆盖旧证据。
4. 发布只作为后续授权动作。使用同一候选镜像更新 backend/worker，先迁移内部 probe job 表，再启用调度；旧结果不回填。升级/回滚时停止接新 job并有界结束在途执行。
5. 回滚上一镜像和依赖锁时先处理新格式内部 job，避免旧 worker 消费不认识的消息。无静默运行时 fallback；若部署回滚旧镜像，会恢复旧转换实现，应明确其版本边界。

## 实施中确认的受控补丁（2026-10-30）

用户已明确批准为固定 OpenCodex 2.94.0 纳入一处 EOF 修补并继续实施。原版在 `src/adapters/openai-chat.ts` 的流结束分支只在无文本时拒绝缺少终态；已有文本但无 finish_reason / [DONE] 会合成 completed，真实 Codex 0.165.0 随之零退出。把 `if (!sawFinish && !sawUserFacingOutput)` 改为 `if (!sawFinish)` 后，同一夹具返回 response.failed，真实 CLI 非零退出，正常响应/明确长度截断/已测错误行为保持正确。

此补丁独立记录原始文件和修补文件 SHA-512，原版本/内容不匹配时构建失败；项目维护补丁应用脚本及独立单元测试，受修改逻辑进入对应的协议回归和分支验证。它不授权新增第二套转换器、其它未经验证第三方补丁或降低协议要求。升级第三方时重新判断是否可移除补丁，保留许可证和来源。

无关联的 function_call_output 会被第三方透传，属于已批准请求准入层的输入合法性校验范围，应在上游调用前拒绝。

## 内容类型修补授权（2026-11-02）

用户在了解具体缺陷后明确同意进行补丁修复。固定 OpenCodex 的 `chatContentEvents` 会静默丢弃非法数值/布尔值/对象型 content，并在后续正常终止时报告 completed。已批准第二处修补保留合法字符串、null/undefined 和现有数组处理，把非法类型映射到受控上游错误。两处补丁统一由 `patch_eof.py` 预校验版本及全部目标文件哈希后应用，安装清单逐项记录原始与结果 SHA-512。
